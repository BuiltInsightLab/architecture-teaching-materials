廠務案例：TIAA 語意執行
與跨域傳播完整過程

以空調箱冷凍機效率異常、超純水系統壓差異常為例，展示可插拔語意執行框架（SAM）從感測觸發到跨域傳播的完整決策鏈。

黃千溥 助理教授 · 國立臺北科技大學 HTFA 2026 · 台中新烏日 · 2026.06.12
研究說明影片

系統概念介紹

以下影片說明本研究核心概念——如何透過可插拔領域知識模組，讓設施管理系統快速部署、跨域複用，並保留完整的決策稽核紀錄。

框架概念

可插拔領域知識模組（Domain Packs）

每一個 Domain Pack 封裝特定領域的觸發條件、語意規則、執行動作與稽核邏輯。同一套通用執行環境（SAM Runtime）可載入不同 Pack，無需重新開發即可處理新場域。

T  Trigger 觸發→ I  Issue 議題→ A  Action 行動→ Ac Actor 執行者→ P  Propagation 跨域傳播

TIAA 是最小可執行語意單元。每個感測異常事件被解析為完整的四元組，執行完畢後透過 Propagation 機制向鄰近知識域廣播，維持整體系統語意一致性。

案例一

空調箱冷凍機效率異常 — HVAC PdM Pack

半導體廠潔淨室的空調箱依賴冷凍機維持恆溫恆濕。當冷凍效率下降，晶圓良率直接受影響。以下展示 HVAC PdM Pack 如何完成從感測到派工，再到跨域傳播的完整鏈路。

❄️
HVAC PdM Domain Pack
冷凍機效率異常偵測與維修派工
監測對象：AHU-B3-07 冷凍機組 · COP < 3.2 或 ΔT > 5°C 持續 15 分鐘
T
Trigger · 感測觸發
溫度與能效感測器回報異常
AHU-B3-07 的 COP 連續 18 分鐘低於閾值，Neo4j 即時查詢觸發語意驗證流程。

SHACL 語意約束規則：定義「什麼情況下算異常」，系統自動比對感測值是否觸發。

// SHACL 觸發規則
sh:ChillerCOPConstraint
  sh:path         fab:currentCOP ;
  sh:maxInclusive 3.2 ;
  sh:minCount     1 .

// Neo4j Cypher — 異常偵測
MATCH (s:Sensor)-[:MONITORS]->(c:Chiller)
WHERE s.COP < 3.2
  AND duration.between(s.lastNormal, s.now).minutes > 15
RETURN c.id, s.COP, s.timestamp
I
Issue · 語意議題解讀
冷凍效率衰退（可能：冷媒洩漏、熱交換器結垢、壓縮機磨損）
LLM 推論引擎結合歷史維修紀錄與設備參數，將感測數值轉化為可理解的設施管理議題，評估風險等級。
Issue {
  id:            "ISS-2026-0612-001",
  type:          "ChillerEfficiencyDegradation",
  severity:      "HIGH",
  affectedAsset: "AHU-B3-07",
  probableCause: ["refrigerant_leak", "fouling"],
  impactZone:    "CleanroomB3",
  riskScore:     0.82
}
A
Action · 自動執行動作
建立工單 + AAST 判斷是否需人工升級
系統自動建立 WorkOrder，AAST 機制判斷風險是否超過自動執行門檻。
WorkOrder {
  id:            "WO-2026-0612-038",
  priority:      "URGENT",
  type:          "ChillerInspection",
  sla:           "4h",
  linkedIssue:   "ISS-2026-0612-001",
  autoGenerated: true
}
⚖️
AAST 判斷：風險評分 0.82 超過門檻（0.75），系統自動升級通報設施主管，並暫停非必要冷卻負載調度，等待人工確認後再執行設備停機。
Ac
Actor · 執行者指派
廠務工程師（冷凍空調）+ 設施主管（核准停機）
根據技能矩陣與當班排班自動指派責任工程師。所有決策步驟由 PROV-O 記錄，可完整重建執行路徑。

PROV-O 稽核紀錄：記錄「誰、何時、根據哪筆資料、做了什麼決定」，可完整重建執行路徑。

// PROV-O 稽核紀錄
prov:Activity { id: "exec-WO-038" }
  prov:wasAssociatedWith :Engineer_Lin ;
  prov:wasInformedBy     :Issue-001 ;
  prov:startedAtTime     "2026-06-12T14:52:03Z" ;
  prov:used              :ChillerSensorReading-4821 .
P
Propagation · 跨域傳播
執行結果向鄰近知識域廣播，維持整體語意一致性
WO-038 執行完畢後，SAM Runtime 自動識別受影響的鄰近域，以標準化語意事件格式傳遞更新訊息，無需人工通知。
// 跨域傳播事件（SAM Propagation Bus）
PropagationEvent {
  source:    "HVAC-PdM-Pack",
  trigger:   "WO-038-completed",
  timestamp: "2026-06-12T16:34:00Z",
  targets:   ["EnergyMonitoring", "ProductionScheduling", "AssetLifecycle"]
}
→
能源監控域
標記 14:35–16:34 該機組能耗異常區間；更新月度能效基準值。
→
生產排程域
預警 CleanroomB3 可能降溫 90 分鐘；建議排程調整 Wet-Etch-A 站台優先級。
→
設備履歷域
更新 AHU-B3-07 維修紀錄；觸發下次預防保養提前計算（MTBF 重估）。
案例二

超純水系統壓差異常 — UPW Monitoring Pack

超純水（UPW）是半導體製程清洗用水，水質與水壓直接影響良率。以下展示同一套 SAM 框架換上 UPW Monitoring Pack 後的執行過程——框架完全不動，只換了知識模組。

💧
UPW Monitoring Domain Pack
濾膜堵塞偵測與緊急換濾作業
監測對象：UPW-LOOP-F03 過濾器組 · ΔP > 0.3 bar 且持續 5 分鐘
T
Trigger · 感測觸發
壓差感測器偵測到濾膜前後壓力差超標
UPW Loop F03 進出口壓差在 6 分鐘內維持在 0.34 bar，觸發 SHACL 語意驗證。

SHACL 語意約束規則：定義濾膜更換的壓差門檻，系統自動比對是否觸發換濾流程。

sh:UPWPressureConstraint
  sh:path         fab:differentialPressure ;
  sh:minInclusive 0.30 ;
  sh:message      "Filter fouling threshold exceeded" .

ΔP_in:  2.41 bar（進水）
ΔP_out: 2.07 bar（出水）
ΔP:     0.34 bar  →  TRIGGER ✓
I
Issue · 語意議題解讀
過濾器堵塞——預估剩餘壽命 < 8 小時，供水量即將不足
知識圖譜結合歷史堵塞曲線與壓差變化率，推算最遲換濾時限，並評估影響的下游製程站台。
Issue {
  type:                   "UPWFilterFouling",
  severity:               "CRITICAL",
  affectedFilter:         "UPW-LOOP-F03",
  estimatedTimeToFailure: "6.5h",
  downstreamImpact:       ["Wet-Etch-A", "CMP-B"],
  riskScore:              0.91
}
A
Action · 自動執行動作
緊急換濾工單 + 下游預警 + 備用庫存確認
風險評分 0.91 直接觸發緊急流程，同時查詢備料庫存、計算換濾時間窗口，並通知生產排程調整。
Step 1: CREATE WorkOrder(type: EmergencyFilterChange, sla: 2h)
Step 2: QUERY Inventory("UPW-F03-membrane") → stock: 4 units ✓
Step 3: NOTIFY ProductionScheduler(
          downtime: 90min,
          stations: ["Wet-Etch-A", "CMP-B"])
Step 4: ESCALATE FacilityManager(reason: riskScore > 0.9)
⚖️
AAST 強制升級：風險評分 0.91 超過緊急門檻（0.85），系統鎖定自動換濾決策，要求設施主管在 15 分鐘內確認作業，確保人為監督不被跳過。
Ac
Actor · 執行者指派
廠務工程師（UPW 系統）+ 生產主管（排程協調）
系統自動指派 UPW 專責工程師，並通知生產排程主管協調停線時間窗口。

PROV-O 稽核紀錄：同樣格式，確保 UPW 案例的決策路徑可被完整重建與稽核。

prov:Activity { id: "exec-WO-UPW-041" }
  prov:wasAssociatedWith :Engineer_Chen ;
  prov:wasAssociatedWith :Manager_Production ;
  prov:used              :FilterPressureReading-9923 ;
  prov:used              :InventoryQuery-result ;
  prov:endedAtTime       "2026-06-12T16:18:44Z" .
P
Propagation · 跨域傳播
換濾完成後，更新水質履歷並重啟下游站台供水
換濾作業完成後，SAM Runtime 自動向相關域廣播恢復訊號，確保各子系統語意狀態同步更新，無需人工逐一通報。
PropagationEvent {
  source:    "UPW-Monitoring-Pack",
  trigger:   "WO-UPW-041-completed",
  timestamp: "2026-06-12T16:18:44Z",
  targets:   ["WaterQualityRecord", "ProductionScheduling", "SupplyChain"]
}
→
水質履歷域
記錄本次堵塞事件至濾膜使用履歷；更新下次預防換濾時間（依壓差曲線重新預估）。
→
生產排程域
發送恢復訊號至 Wet-Etch-A 與 CMP-B；解除預警狀態，站台可重新排入生產佇列。
→
供應鏈域
觸發備用濾膜採購申請（庫存剩 3 件，低於安全水位 5 件）；連結採購 Pack 自動下單。
